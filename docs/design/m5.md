# M5 design — pipeline + real LLM adapters + CLI

Status: **implemented (M5.a + M5.b + M5.c).** Makes the runtime
end-to-end usable without custom glue.

## Goal

Turn Ontos from "four islands you have to stitch together" into
"point it at a directory and let it ingest, then ask questions."
The three pieces:

1. **IngestPipeline** (M5.a) — the wire that connects Connector →
   Extractor → Resolver → Store.
2. **Real LLM adapters** (M5.b) — Ollama (sovereignty default) and
   OpenAI (bridge) so `ask()` runs without writing a custom
   `LLMBackend`.
3. **`ontos` CLI** (M5.c) — operator entry points for `serve`,
   `ingest`, `query`, and `audit verify`.

## IngestPipeline (M5.a)

```python
IngestPipeline(
    connector=connector,
    extractor=extractor,
    resolver=resolver,  # optional; pass None to skip ER
    store=store,
    error_policy=ErrorPolicy.FAIL_FAST | ErrorPolicy.SKIP_AND_LOG,
)
report = await pipeline.run()
```

Stateless — `run()` can be called multiple times with the same
instance; all state lives in the components it composes.

### Error policy

- **`FAIL_FAST`** (default) — the first `ExtractionError`
  propagates. Right for interactive ingest where operators want to
  see the first broken source and fix it.
- **`SKIP_AND_LOG`** — errored sources land in
  `IngestReport.errors`; ingest continues. Right for batch runs
  over large corpora where isolated bad docs shouldn't kill the
  run.

**Never silent-drops.** Every skipped source shows up in the report
so the operator sees exactly what didn't land.

### ACL propagation

`SourceDocument.acl_ref` flows onto `Fact.acl_ref` when the fact
didn't already declare one. This is how per-source authz from the
connector layer reaches the store's traversal-time filter without
any pipeline-level policy logic.

## Real LLM adapters (M5.b)

Two adapters shipped. Both satisfy `LLMBackend` (extraction) AND
`LLMPlannerBackend` (planning) — one class, two callables.

### `OllamaBackend` — sovereignty default

Local, no auth, in-VPC. This is the recommended default and the
first adapter shipped. Uses Ollama's `/api/chat` with `format`
set to a JSON Schema (Ollama 5.0+) — the model is constrained to
the exact response shape.

- httpx.AsyncClient injectable for tests → no real network in CI.
- Any Ollama-hosted model that supports structured outputs works
  (llama3, mistral, qwen2.5, phi4, gemma3).

### `OpenAIBackend` — bridge

**BRIDGE. Marked in the module docstring.** Sending prompts to
`api.openai.com` violates the in-VPC sovereignty promise; use it
for dev and prototyping, never in a regulated customer deploy.
**Enclave Scribe replaces this once its extraction and planning
benchmarks pass current frontier models.**

- Uses OpenAI's `chat.completions.parse` with Pydantic
  `response_format` — structured outputs are hard-typed. No
  JSON-parse-repair fallback, no silent-empty.
- Deferred `openai` import; behind the `openai` optional extra.

### Shared prompt templates

`ontos/llm/prompts.py` holds the extraction + planner prompts so
all backends speak the same shape. Provider-specific structured-
output wrapping (function calls / json_schema / mode) is the
backend's concern; the CONTENT of the prompt lives in one place.

## `ontos` CLI (M5.c)

Typer-based. Four commands, deferred-import for `--help` speed.

| Command | Purpose |
|---|---|
| `ontos serve` | Boot the FastMCP server (equivalent to the old `python -m ontos.runtime.server`). |
| `ontos ingest --source-dir --ontology [--ollama-model --ollama-url --error-policy]` | Walk a directory of .txt/.md files → TextConnector → OllamaBackend LlmExtractor → ExactMatchResolver → configured GraphStore. Prints the `IngestReport` as JSON. |
| `ontos query "..." --ontology` | Run one NL question through LlmPlanner + DeterministicExecutor locally. Prints plan + ranked hits + warnings. |
| `ontos audit verify --db-url` | Walk the Postgres audit chain and report tampering. Exits 1 on tampering (CI-friendly). |

### Package entry point

Moved from `ontos.runtime.server:main` to `ontos.cli.main:app`.
`serve` remains available and behaviorally identical — `uv run
ontos serve` matches what the old `uv run ontos` used to do.

## What we deliberately NOT doing in M5

- **Anthropic adapter** — same shape as OpenAI (structured outputs
  via tool-use); trivial to add when we have a customer asking. The
  primary Anthropic use case at Enclave is `claude-sonnet-5` for
  agent-facing calls, which is Enclave-runtime's job, not Ontos's.
- **CLI's `serve` reading a fully-composed config file** — for now
  server config is via env vars (the deploy story via the Helm
  chart handles this cleanly). A `--config ontos.toml` follow-up
  when operators actually complain about env-var sprawl.
- **`ontos ingest` running the executor for query-in-a-loop** —
  ingest and query are separate commands on purpose; a "does the
  ingested graph answer the question?" workflow is either a
  benchmark harness invocation (M3.d) or a shell one-liner.

## Roadmap tie-ins

- **Vertical launch package (option B from "what next?" fork)** —
  M5's `ontos ingest` + real ontologies for fintech/pharma/legal/
  defense = a real quickstart. That's the next natural block.
- **`ontos ingest` end-to-end integration test against real Ollama**
  — behind a new `slow` pytest marker; smoke-tests the real
  Ollama roundtrip without gating CI on Ollama being installed
  everywhere.
- **Enclave Scribe cutover** — `OllamaBackend` and `OpenAIBackend`
  become the reference adapters that `ScribeBackend` replaces via
  the same Protocol. Both can run side-by-side on a benchmark
  corpus during the switch.

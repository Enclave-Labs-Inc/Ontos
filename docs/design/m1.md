# M1 design — Neo4j storage + provenance-wrapped extraction

Status: **design, pre-implementation.** This doc pins the load-bearing decisions before code so we don't rewrite twice. If a decision changes during implementation, update this file in the same PR — it is authoritative.

## Goal

By end of M1, Ontos boots against a real Neo4j instance, ingests a sample corpus through the LlamaIndex/LangChain extraction path with provenance wrapping, and answers `search / traverse / explain / provenance / audit` end-to-end. Every returned fact carries a full `Provenance` chain; every query emits an Article-12 audit record; permission-aware traversal enforced in Cypher, not post-filtered.

## Six locked decisions (from Round-4 research on neo4j-graphrag-python + LangChain LLMGraphTransformer)

1. **Build on `neo4j-graphrag-python`** (the official pip library), **not** the standalone LLM Graph Builder UI app. The UI app just wraps this library; we want the library directly.
2. **Manual `Pipeline` from day one.** `SimpleKGPipeline` only lets us plug in `text_splitter / file_loader / kg_writer` — we need to override extractor, writer, resolver, and pruner. Manual pipeline it is.
3. **Subclass `LLMEntityRelationExtractor`** to enrich each triple with `(source_id, extractor_id, extractor_version, confidence, confidence_score, t_valid, t_invalid, ingested_at)`. LangChain's extractor gives yes/no; confidence derivation is our responsibility.
4. **Subclass `Neo4jWriter`** to emit Cypher that persists our extra fact metadata. The default writer strips anything outside the schema.
5. **Subclass the `EntityResolver`** to preserve merge lineage — audit MUST be able to answer "which original nodes got merged into this canonical entity?"
6. **Force `additional_node_types=False`** and enable `GraphPruner`. Schema strictness prevents the CypherBench-shaped failure modes (schema violations, reversed direction, invented predicates).

## Module contracts

The public interfaces below are the contract every M1 PR must satisfy. Downstream code (planner, executor, MCP tools) only touches these.

### `ontos/extraction/base.py`

The Scribe-drop-in boundary. Nothing downstream may import LlamaIndex or LangChain types past this file.

```python
class ExtractionInput(BaseModel):
    source_id: str            # stable id of the source doc/message/row
    text: str
    metadata: dict[str, str]  # bag; e.g. {"filename": ..., "author": ...}

class ExtractionResult(BaseModel):
    facts: list[Fact]         # every Fact has full Provenance already attached
    entities: list[Entity]    # canonicalized entity records
    warnings: list[str]       # non-fatal issues surfaced for the audit trail

class Extractor(Protocol):
    async def extract(self, input: ExtractionInput) -> ExtractionResult: ...
    @property
    def id(self) -> str: ...          # e.g. "llama-index-pgi" or "enclave-scribe"
    @property
    def version(self) -> str: ...     # e.g. "0.11.0"
```

**Invariants any implementation must uphold:**
- Every `Fact` in the result has a fully populated `Provenance`. Never emit a partial one.
- `t_valid` defaults to `ingested_at` unless the source provides a stronger claim (e.g. a filing date).
- Confidence labels are calibrated per implementation — document the calibration in the impl module.

### `ontos/extraction/llm_extractor.py`

> **Naming divergence from the original design.** The doc first named this
> file `llama_index.py` and described it as wrapping neo4j-graphrag-python's
> `LLMEntityRelationExtractor`. In implementation (see M1.d) that subclass
> path required reaching past the neo4j-graphrag public API for every
> enrichment we care about (provenance, confidence, schema-strict filtering).
> Instead the module now defines a small `LLMBackend` protocol that any
> provider (OpenAI, Anthropic, neo4j-graphrag's `LLMInterface`, Scribe)
> adapts to, and implements the extractor pipeline directly. Same
> design intent, cleaner testability, no lock-in to a specific LLM
> framework. The `Extractor` Protocol from `base.py` is unchanged so
> nothing downstream cares.

```python
class LLMBackend(Protocol):
    """Narrow LLM surface any provider adapts to."""
    id: str
    version: str
    async def structured_extract(self, text: str, ontology: Ontology) -> list[RawTriple]: ...

class LlmExtractor(Extractor):
    """LLM-backed extractor with schema-strict filtering, provenance
    enrichment, calibrated confidence, and loud-fail on silent-empty."""
```

## Cypher patterns (the load-bearing bit)

### Entity nodes

Entities are canonical (post-resolution). Every entity carries a stable `id` and its type as a label:

```cypher
(:Entity:Person {id: "person:alice", canonical_name: "Alice Smith"})
```

Labels are additive — `:Entity` is always present; the type label (`:Person`, `:Company`, …) is added from the ontology.

### Facts as edge properties (not reified)

For M1, facts are relationships with metadata on the edge. Reified `Fact` nodes are a future option if provenance-heavy queries need it.

```cypher
(a:Entity)-[r:RELATES {
    fact_id: "uuid...",
    predicate: "acquired",
    t_valid: datetime("2025-03-14T00:00:00Z"),
    t_invalid: null,
    ingested_at: datetime("2026-09-25T14:22:00Z"),
    superseded_by: null,
    acl_ref: null,
    prov_source_id: "sec-edgar:0001234-25-000001",
    prov_extractor_id: "llama-index-pgi",
    prov_extractor_version: "0.11.0",
    prov_confidence: "EXTRACTED",
    prov_confidence_score: 0.98
}]->(b:Entity)
```

We use a single `:RELATES` relationship type with `predicate` as a property (not one relationship type per predicate). This keeps the schema stable when the ontology evolves and matches the shape our `Fact` model already assumes.

### `search` — text match filtered by validity + ACL

```cypher
MATCH (a)-[r:RELATES]->(b)
WHERE r.t_valid <= $as_of
  AND (r.t_invalid IS NULL OR r.t_invalid > $as_of)
  AND (r.acl_ref IS NULL OR r.acl_ref IN $allowed_acls)
  AND toLower(a.canonical_name + " " + r.predicate + " " + b.canonical_name) CONTAINS toLower($needle)
RETURN r, a, b
LIMIT $k
```

M1 uses simple `CONTAINS` for parity with the NetworkX store. Full-text and vector hybrid land in M3.

### `traverse` — permission-aware, no node-existence leaks

Every edge in every returned path must pass the ACL check. If one edge is forbidden, the whole path is dropped — the target node is never returned, so its existence never leaks.

```cypher
MATCH path = (start:Entity {id: $start_id})-[rels:RELATES*1..$depth]->(end:Entity)
WHERE ALL(r IN rels WHERE
    r.t_valid <= $as_of
    AND (r.t_invalid IS NULL OR r.t_invalid > $as_of)
    AND (r.acl_ref IS NULL OR r.acl_ref IN $allowed_acls)
    AND ($relation IS NULL OR r.predicate = $relation)
)
RETURN path
```

**Why this shape:** the `ALL(...)` on `rels` prunes at query time — Neo4j's execution engine drops the path before materializing the endpoint. Post-filtering the results would leak node existence via counts / partial responses.

### Supersession — never in-place mutation

```cypher
// Close the old fact
MATCH ()-[r:RELATES {fact_id: $old_fact_id}]->()
SET r.t_invalid = $now, r.superseded_by = $new_fact_id

// Write the new fact as a new edge
MATCH (a:Entity {id: $subject_id}), (b:Entity {id: $object_id})
CREATE (a)-[:RELATES {
    fact_id: $new_fact_id,
    predicate: $predicate,
    t_valid: $now,
    ingested_at: $now,
    ...
}]->(b)
```

### Indexes (created at store init)

```cypher
CREATE INDEX entity_id_idx IF NOT EXISTS FOR (n:Entity) ON (n.id);
CREATE INDEX fact_id_idx IF NOT EXISTS FOR ()-[r:RELATES]-() ON (r.fact_id);
CREATE INDEX fact_predicate_idx IF NOT EXISTS FOR ()-[r:RELATES]-() ON (r.predicate);
CREATE INDEX fact_validity_idx IF NOT EXISTS FOR ()-[r:RELATES]-() ON (r.t_valid, r.t_invalid);
```

The `t_valid, t_invalid` composite matters — every read query filters on it, so this is the hot path.

## What we're deliberately NOT doing in M1

- **Full text + vector hybrid retrieval** — `CONTAINS` for search suffices to prove the pipeline. M3 upgrades to hybrid + PPR + PathRAG pruning.
- **OpenFGA integration** — `acl_ref` is a plain string match in M1. M2 replaces with `Check(user, relation, object)`.
- **Persistent hash-chained audit log in Postgres** — M0's in-memory chain still runs. M2 persists it.
- **Query planner** — the LLM calls MCP tools directly with simple args. M3 introduces the typed-plan / deterministic-executor split.
- **Streaming CDC ingestion** — M1 ingests batches. M4 adds real-time.
- **Confidence calibration model** — M1 emits a confidence score derived from the LLM's own reported likelihood or from token-agreement over multi-sample. A trained calibrator is a Scribe-era concern.

## Risks & how we mitigate them

- **LangChain `LLMGraphTransformer` silent-empty-on-parse-error bug.** Our subclass wraps every extraction call; on empty output we raise `ExtractionError` with the offending text sample and fail the ingestion. Better a loud fail than a silent-empty graph.
- **`additional_node_types=True` by default.** We set it to `False` at pipeline construction and add a startup assertion.
- **Property key `"id"` fails at runtime.** Our schema validator rejects any ontology that names a property `"id"`; entities use `entity_id` and edges use `fact_id`.
- **Structured-output backend is required** (function-calling path). We refuse to boot if the configured LLM isn't OpenAI / Anthropic / Vertex until Scribe ships. Ollama users get a clear error, not a fragile JSON-parse fallback.
- **`EntityResolver` merges are irreversible in the base class.** Our subclass writes a `(:MergeRecord)` node per merge with the pre-merge entity ids and a timestamp, so audit can reconstruct the history.

## When Scribe replaces LlamaIndex

`ontos/extraction/scribe.py` implements the same `Extractor` Protocol. Ontology, storage, planner, executor, MCP tools, audit — all unchanged. A config flag switches the default extractor. Both extractors can run in parallel on a benchmark corpus during the cutover to compare per-fact accuracy and calibration.
